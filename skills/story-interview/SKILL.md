# story-interview · 采访

传记是采访的依据，采访是传记的来源。这个 skill 负责 data flow 里的「问」：读已有的
biography、MEMORY 与近期 transcript，判断「还有什么值得问」，然后通过提问把用户脑中
尚未说出的 context 引出来。产出的访谈最终经 story-write 与 transcript 同等消化回传记，
形成「越了解 → 越会问 → 越了解」的循环。

## 第一步：确定模式

两种模式都是完整能力，按用户意图选择：

- **离线访谈录**：用户说「生成今天的访谈录/问题清单」「我想对着录音回答」时使用。
  产出一份当日问题文档，用户之后自己录音回答，走 listen → transcribe → write 回流。
- **交互访谈**：用户说「采访我」「进入访谈」「聊聊今天」时使用。一次只问一个问题，
  根据回答渐进深挖，挖得更深，但需要用户在场。

用户没有明确指向时，先问一句想用哪种模式，不要擅自替用户选。

## 第二步：收集 context

无论哪种模式，先运行规划脚本拿到确定性汇总：

```bash
node skills/story-interview/scripts/context.js
# --days=14  调整近期转写的时间窗口（默认 14 天）
```

输出 JSON 含：传记大纲（各小节标题与覆盖时段）、MEMORY 路径、近期已转写录音（及是否
已入传）、访谈历史（避免重复提问）。然后：

1. **完整读 `~/.storytelling/MEMORY.md`**——这个人的身份、重要的人、主线、时间线。
2. **通读近期 transcript**（context.js 给出的路径）。不是浏览，是通读——近期的心境、
   未展开的话题、提到但没说透的事，都是今天值得问的线索。
3. **扫传记大纲与访谈历史**：传记哪里单薄、哪里缺失、哪里前后模糊；之前问过什么，
   不要重复。
4. **查待访谈清单**：`~/.storytelling/interviews/` 下的待访谈条目（story-research /
   story-write 沉淀的「检索无果 + 空占位页」清单）是空白填补问题的直接来源。但提问前
   **先在 Notion 语料与已有传记里 search/grep 一遍**，确认这个空白是真的空——很多「看似
   空白」的东西其实早已写在语料的某个角落，问用户之前先替用户找过一遍。确认无果的才
   列为访谈问题。

## 第三步A：离线访谈录

1. 拟定 **5–8 个问题**，两类搭配：
   - **今日引导**（2–3 个）：开放但有锚点。不是干巴巴的「今天怎么样」，而是基于近况
     的具体引导，如「今天面试官问到 XX 的时候，你当时心里实际在想什么」。
   - **空白填补**（3–5 个）：针对传记中缺失、模糊、前后矛盾处。问题要给足 context
     （把你知道的先摆出来），让用户只需补充，而不是先替你回忆。
2. 问题按「由浅入深、由今天到过去」排序；语气自然，像朋友聊天，不像审讯。
3. 用脚本落盘：

```bash
# questions.json: { "questions": ["问题1", "问题2", ...] }
node skills/story-interview/scripts/save.js --mode=offline --input=questions.json
# --date=YYYY-MM-DD  指定访谈日期（默认今天）
```

4. 告诉用户：对着这份访谈录录音（一段或分几段都行），之后的导入、转写、写传会自动回流。

## 第三步B：交互访谈

1. **一次只问一个问题**。问完就停，听用户说完再追问或进入下一问。这是本模式的全部价值
   ——渐进深挖，绝不能变成一口气列出问题清单让用户逐条回答。
2. 访谈中自然混合两类问题：顺着用户的话往下挖（「你刚才说 XX，后来呢」），比按预设清单
   走更重要；空白填补的问题在合适的时机抛出，不生硬插入。
3. 用户回答时**不要打断整理、不要抢话**；深挖的判断标准是「这个话题还有没有没说出来的
   东西」，而不是问题清单有没有走完。
4. 用户表示结束（或明显疲惫）时收尾，把问答整理落盘：

```bash
# qa.json: { "exchanges": [{ "q": "你问的问题", "a": "用户的回答" }, ...] }
node skills/story-interview/scripts/save.js --mode=interactive --input=qa.json
# --minutes=25  可选：本次访谈大致时长
```

5. **整理原则**：尽可能保留用户原话的真实文本，只去掉口水词（「就是」「那个」「嗯」之类，
   与 ASR 语义顺滑同一标准）；不改写、不总结、不替用户润色——story-write 需要的是原始
   素材，文学化是它的事。你自己的问题保留原样即可。

## 要点

- **问出好问题的前提是真正读了传记**。没读 context 就发问，是审讯；读了 context 再问，
  才是采访。
- 空白填补的问题宁可具体而小（「2026-07-16 定 offer 那天，你第一反应是什么」），
  不要大而空（「谈谈你的求职经历」）。
- 每次访谈结束记得落盘——没有落盘的访谈等于没发生过。
- 敏感处不强推：用户明显回避某个话题时，退一步换角度或干脆留待下次，传记不缺这一块。
