# story-interview · 采访

传记是采访的依据，采访是传记的来源。这个 skill 负责 data flow 里的「问」：读已有的
biography、MEMORY 与近期 transcript，判断「还有什么值得问」，然后通过提问把用户脑中
尚未说出的 context 引出来。产出的访谈最终经 story-write 与 transcript 同等消化回传记，
形成「越了解 → 越会问 → 越了解」的循环。

## 第一步：确定主题与形式

采访有**两个正交维度**，先定主题、再定形式：

**主题**——问什么：
- **补全过去**（默认）：针对传记中缺失、模糊、前后矛盾处，把用户脑中尚未说出的过往挖出来。
- **今日日记**：引导用户讲述**今天的经历与感受**，动态追踪每天的近况。日记访谈的地位与
  录音素材等同，产物同样回流 story-write 沉淀。用户说「记一下今天」「日记模式」「聊聊今天
  过得怎么样」时选这个。

**形式**——怎么问：
- **离线访谈录**：用户说「生成今天的访谈录/问题清单」「我想对着录音回答」时使用。
  产出一份当日问题文档，用户之后自己录音回答，走 listen → transcribe → write 回流。
- **交互访谈**：用户说「采访我」「进入访谈」时使用。一次只问一个问题，根据回答渐进
  深挖，挖得更深，但需要用户在场。

主题与形式自由组合（如「日记 + 交互」「补全 + 离线」）。落盘只跟形式走，与主题无关。
用户没有明确指向时，先问一句想用哪种，不要擅自替用户选。

## 第二步：收集 context

无论哪种组合，先运行规划脚本拿到确定性汇总：

```bash
node skills/story-interview/scripts/context.js
# --days=14  调整近期转写的时间窗口（默认 14 天）
```

输出 JSON 含：传记大纲（各小节标题与覆盖时段）、MEMORY 路径、近期已转写录音（及是否
已入传）、访谈历史（避免重复提问）。然后：

1. **完整读 `~/.storytelling/MEMORY.md`**——这个人的身份、重要的人、主线、时间线。
2. **通读近期 transcript**（context.js 给出的路径）。不是浏览，是通读——近期的心境、
   未展开的话题、提到但没说透的事，都是今天值得问的线索。
3. **扫传记大纲与访谈历史**：传记哪里单薄、哪里缺失、哪里前后模糊；之前问过什么，
   不要重复。
4. **按主题侧重**：
   - **补全过去**：传记空白就是问题来源。查待访谈清单——`~/.storytelling/interviews/`
     下的待访谈条目（story-research / story-write 沉淀的「检索无果 + 空占位页」清单）。
     但提问前**先在 Notion 语料与已有传记里 search/grep 一遍**，确认这个空白是真的空
     ——很多「看似空白」的东西其实早已写在语料的某个角落，问用户之前先替用户找过一遍。
     确认无果的才列为访谈问题。
   - **今日日记**：传记空白与待访谈清单**默认不用**。重点看近期 transcript 与最近的
     日记访谈——昨天/前几天聊过什么、用户的近况线（在推进的事、最近的情绪、悬而未决
     的事），都是今天提问的连续性锚点。

## 第三步A：离线访谈录

1. 拟定 **5–8 个问题**，构成按主题区分：
   - **补全过去**：**空白填补**（3–5 个）针对传记中缺失、模糊、前后矛盾处，问题要给足
     context（把你知道的先摆出来），让用户只需补充，而不是先替你回忆；搭配少量**今日
     引导**（2–3 个）开放但有锚点，不是干巴巴的「今天怎么样」，而是基于近况的具体引导，
     如「今天面试官问到 XX 的时候，你当时心里实际在想什么」。
   - **今日日记**：全部为**今日引导**——围绕今天的经历与感受，基于近况给锚点（「今天
     XX 的事后来怎么样了」），引导用户按今天的自然展开顺序讲出来，经历与感受并重。
     默认不掺空白填补类问题。
2. 问题按「由浅入深、由今天到过去」排序（日记主题则由浅入深、顺今天的时间线）；语气
   自然，像朋友聊天，不像审讯。
3. 用脚本落盘：

```bash
# questions.json: { "questions": ["问题1", "问题2", ...] }
node skills/story-interview/scripts/save.js --mode=offline --input=questions.json
# --date=YYYY-MM-DD  指定访谈日期（默认今天）
```

4. 告诉用户：对着这份访谈录录音（一段或分几段都行），之后的导入、转写、写传会自动回流。

## 第三步B：交互访谈

1. **一次只问一个问题**。问完就停，听用户说完再追问或进入下一问。这是本模式的全部价值
   ——渐进深挖，绝不能变成一口气列出问题清单让用户逐条回答。
2. 顺着用户的话往下挖（「你刚才说 XX，后来呢」），比按预设清单走更重要。
3. **按主题掌握方向**：
   - **补全过去**：空白填补的问题在合适的时机抛出，不生硬插入。**横向优先，深挖在后**
     ——优先沿时间线做横向补全，一个个阶段、地点、事件地问过去，把没说出口的部分挖出来；
     对单个话题的深度追问（场合、感受、来龙去脉的回忆考古）要克制，先自问「这个问题用户
     大概率还记得吗」——不记得的概率高就换话题。等横向时间线填充得差不多了，再回头做
     深度挖掘。
   - **今日日记**：顺用户今天的时间线与事件走，把经历与感受都引出来（「那件事发生时你
     是什么感觉」）；默认不主动把话题往过去拉。用户自己提了一嘴过往、且恰好关联传记空白
     时，可以顺势接一两句——灵活，但不默认掺空白填补。
4. 用户回答时**不要打断整理、不要抢话**；深挖的判断标准是「这个话题还有没有没说出来的
   东西」，而不是问题清单有没有走完。
5. 用户表示结束（或明显疲惫）时收尾，把问答整理落盘：

```bash
# qa.json: { "exchanges": [{ "q": "你问的问题", "a": "用户的回答" }, ...] }
node skills/story-interview/scripts/save.js --mode=interactive --input=qa.json
# --minutes=25  可选：本次访谈大致时长
```

6. **整理原则**：尽可能保留用户原话的真实文本，只去掉口水词（「就是」「那个」「嗯」之类，
   与 ASR 语义顺滑同一标准）；不改写、不总结、不替用户润色——story-write 需要的是原始
   素材，文学化是它的事。你自己的问题保留原样即可。

## 要点

- **问出好问题的前提是真正读了传记**。没读 context 就发问，是审讯；读了 context 再问，
  才是采访。
- 空白填补的问题宁可具体而小（「2026-07-16 定 offer 那天，你第一反应是什么」），
  不要大而空（「谈谈你的求职经历」）。
- 日记主题的问题同理：锚在具体事件上（「今天和导师聊完之后你的感觉如何」），不要大而空
  （「今天过得怎么样」）。
- 每次访谈结束记得落盘——没有落盘的访谈等于没发生过。
- 敏感处不强推：用户明显回避某个话题时，退一步换角度或干脆留待下次，传记不缺这一块。
- 访谈的价值密度来自「用户没说出口但记得」的部分，而不是「用户可能早就不记得」的部分。
  与其逼问细节，不如推进到下一段时间线。
